  "/images/team/07.jpg",

  # Branding

  $url = $base + $path
  $out = Join-Path $dest ($path.TrimStart("/").Replace("/", "\"))
  $dir = Split-Path $out
  if (!(Test-Path $dir)) { New-Item -ItemType Directory -Path $dir -Force | Out-Null }
  Write-Host "Downloading $url"
  Invoke-WebRequest -Uri $url -OutFile $out -UseBasicParsing
}

Write-Host "Done."

Why this structure works:

- **`public/images/...`** — best for permanent site media the browser should access directly.
- **`brand/`** — logo, favicons, loader assets.
- **`backgrounds/`** — hero and section backgrounds, usually `fill`-based or CSS background images.
- **`team/`** — profiles and biographies.
- **`clients/`** — both carousel images and partner/accreditation logos, separated for clarity.
- **`testimonials/`** — placeholder avatars and real future testimonial portraits.
- **`slides/`** — hero slider assets if we keep the homepage slider concept.

Practical guidance:

- Download the assets once and keep the original source names in the `docs/_/inspo/downloaded-images/` folder for traceability.
- Rename to semantic names in `public/` only after approval, so it stays easy to understand in code.
- Prefer storing only approved brand assets in `public/`; keep raw inspo downloads under the docs folder until we decide what to use.

- **Hero backgrounds** — all parallax `background-image` via jarallax. In the new implementation use Next.js `<Image>` with `fill` and a wrapper div, or a plain `<div style={{ backgroundImage: "url(...)" }}>` for the parallax effect.
- **Team profile pictures** — `images/team/01–07.jpg` map to the seven named staff members in `whychooseus.html`. `soon.jpg` is a placeholder for unassigned roles in `director.html` — these need real photos.
- **`sanni.jpg` vs `sannet.jpg`** — two different images for Sanette: `sannet.jpg` is the full-width hero used on the director page, `sanni.jpg` is a smaller action-box portrait used in the bio section.
- **Testimonial / team placeholders** — `none.jpg` and `soon.jpg` are intentional placeholders; real photos should replace them before launch.
- **`programs.html` and `landing-dashboard.html`** — these two use a *different* asset base (an LMS admin demo, `../assets/img/logo_1784268148.png` / `favicon_1784268148.png`, plus per-program uploads under `../../uploads/programs/*.png|jpg|jpeg`). They aren't covered by the download script above since they resolve against a different host/path than `ndzalama.org.za`; treat them only as a reference for what a "program image" field looks like (one image per course/programme card), not as brand assets to reuse directly.
